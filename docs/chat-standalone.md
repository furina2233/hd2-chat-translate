# 安装、配置与运行

插件在游戏进程内通过两个 WinHTTP 后台线程请求大模型。游戏先显示原文，成功后将对应的本机聊天行更新为 `原文 + 换行 + "译文：" + 译文`。模型判定为中文时保持原文；请求失败时，译文位置显示简短错误提示。消息已经变化、过期或回写门禁失效时保留当前内容。

```text
We need reinforcements at A1
译文：我们需要在 A1 增援
```

模型请求仍只包含原始正文。延迟回写会复用已组合的文字，同一消息不会反复追加“译文：”。

提示词要求整条消息为 `gg` 或 `ggs` 时按中文处理，忽略大小写和首尾空白，显示仍保留原始输入；包含其他英文的句子继续翻译。常用聊天缩写和指定敌人昵称一并交由模型处理，规则与源码位置见 [提示词说明](research.md#提示词与聊天用语)。

正文替换后会重新测量当前行的高度，并按现有历史顺序重新定位消息，让更旧的消息为增加的文字留出空间。此过程保留其他消息的正文及历史索引、计数；成功译文和错误提示使用同一布局流程。接入证据和游戏内验收边界见 [布局说明](native-chat-research.md#多行文字与历史布局)。

## Arsenal 安装与更新

正常关闭游戏，导入 `HD2ChatTranslateYYYYMMDDHHMMSS.zip`，更新同名模组，保持启用并部署。包内包含一个合并 patch，装有 Bingus Shared Loader v18 的原始启动资源和聊天 addon。默认优先级放列表最底端；“第一个模组优先”时放最顶端。旧聊天翻译 addon 不应同时启用。

Arsenal 的 [导入说明](https://docs.rsnl.gg/mod-management/adding-mods) 与 [manifest 说明](https://docs.rsnl.gg/mod-builder/manifest) 说明了 patch 和 `Include` 文件夹的选择方式；包内单个选项只包含 `Addon`。这里的 loader 已放入同一 patch，安装时无需另行导入。

## 环境变量

在 Windows 的“环境变量”设置中配置：

| 变量 | 内容 | 默认 |
| --- | --- | --- |
| `HD2CT_API_URL` | 服务商地址或完整 Chat Completions 请求地址 | 必填 |
| `HD2CT_MODEL` | 账户可用的模型名 | 必填 |
| `HD2CT_API_KEY` | API Key，仅在本机填写 | 必填 |
| `HD2CT_TIMEOUT_SECONDS` | 请求超时，整数 1–120 秒 | `20` |
| `HD2CT_ENABLED` | `0` 禁用翻译，`1` 启用 | `1` |

同名配置优先取用户变量，再取系统变量，最后取进程继承的变量。插件只读取这五个名称，在游戏启动时直接读取持久配置；修改后重启游戏即可。

环境变量以明文保存。密钥不进入安装包、聊天或状态报告。启用后仅把聊天正文发给配置的服务商，不提交玩家账户信息。缺少或无效配置时保留原文。

## URL 补全

| 配置值 | 实际请求地址 |
| --- | --- |
| `https://api.example.com` 或结尾 `/` | `https://api.example.com/chat/completions` |
| `https://api.example.com/v1` 或结尾 `/v1/` | `https://api.example.com/v1/chat/completions` |
| 完整接口或其他自定义路径 | 原样使用 |

只补全根地址和 `/v1`，不纠正拼写。使用正常验证证书的 HTTPS；仅本机回环地址允许 HTTP。地址不接受用户名、密码、查询参数或片段，服务商需支持 Chat Completions 和 JSON mode。重定向被禁用。

## 状态与故障排查

启动后等待约一分钟，发送 `We need reinforcements at A1`。报告位于 `%LOCALAPPDATA%/HD2ChatTranslate/mailbox/chat-translate-<session>.json`；此目录用于状态报告，翻译请求与响应通过进程内 API 传递。检查文件时间是否属于本次游戏会话。

报告应显示 `mode: standalone`、`transport: in_process_winhttp`。`native_init_status`：

| 数值 | 含义 |
| --- | --- |
| `0` | 初始化就绪 |
| `1` | 缺少配置 |
| `2` | 配置或模块无效 |
| `3` | 翻译已关闭 |
| `4` | 后台线程初始化失败 |

`native_last_status` 成功时为 `0`；HTTP 失败使用状态码，如 `401`、`429`；`1000` 为网络错误，`1001` 为响应格式无效，`1002` 为超时。初始化成功却不翻译时，查看是否有提交、译文就绪和回写确认计数；只有旧报告时先检查 Arsenal 是否完成部署及模组优先级。

`layout.verified` 表示高度 helper、直接定位分支及行间隔通过启动核验；`layout.reflows_confirmed` 统计完成测量和历史定位确认的回写次数，`layout.rows_positioned` 统计已确认的位置更新次数。`layout.failures` 记录布局失败，预算不足的延迟不计入其中。`counters.apply_confirmed` 需要正文与布局都通过确认；调用 setter 后确认失败时，本会话停止后续回写。

请求和译文计数增加、正文却不变化时，查看 `layout.last_failure_code`。它只保存固定阶段码，不保存原始异常：

| 代码 | 最近一次布局失败阶段 |
| --- | --- |
| `0` | 尚无失败记录 |
| `1` | 上下文、manager 或地址核验 |
| `2` | 历史读取 |
| `3` | 历史索引或计数范围 |
| `4` | 行内存可写性或分配范围 |
| `5` | 行几何读取 |
| `6` | 纵向缩放范围 |
| `7` | 行高范围 |
| `8` | 目标行不在当前历史中 |
| `9` | 历史发生变化 |
| `10` | 行几何发生变化 |
| `11` | 正文设置及后续测量、定位或确认 |
| `12` | 其他捕获到的异常 |

`last_history_head`、`last_history_count` 是有界历史读数，超出 64 的值统一记作 65。代码为 `6` 或 `7` 时，`last_geometry_slot` 表示失败槽，`last_scale_milli`、`last_height_milli` 是已有几何读数乘 1000 后取整的值；非有限、负数或大于 1000000 的原值记作 0。相应的 `last_scale_class`、`last_height_class` 区分未测量（0）、非有限（1）、负数（2）、零（3）、正常正值（4）和范围不符（5）。这些记录复用预检已经读取的字段，不增加游戏内存读取，也不记录聊天正文、地址或模型配置。

## 请求错误显示

错误提示使用与成功译文相同的双语格式，例如：

```text
We need reinforcements at A1
译文：API 密钥无效
```

| 请求错误码 | 显示提示 |
| --- | --- |
| `HTTP_400`、`HTTP_422` | 请求参数有误 |
| `HTTP_401` | API 密钥无效 |
| `HTTP_403` | 无权使用此接口 |
| `HTTP_404` | 接口或模型不存在 |
| `HTTP_408`、`HTTP_504`、`TIMEOUT`、`EXPIRED` | 请求超时 |
| `HTTP_429`、`RATE_LIMITED` | 请求太频繁，请稍后再试 |
| 其他 HTTP 5xx | 服务暂时不可用 |
| 其他有效 HTTP 状态码 | 请求失败 |
| `NETWORK` | 网络连接失败 |
| `BAD_RESPONSE` 或无效响应 | 返回内容无效 |
| `RESPONSE_TOO_LARGE` | 返回内容过长 |
| `BACKOFF` | 请稍后重试 |
| `INVALID_URL` | 接口地址无效 |
| `INVALID_CONFIG` | 模型配置无效 |
| `INTERNAL` 或捕获到的传输异常 | 翻译服务异常 |
| `SUBMIT_FAILED` | 翻译请求未能提交 |
| `CANCELLED` | 请求已取消 |
| 未知错误码 | 翻译失败，请稍后重试 |

提交、轮询响应和回写适配器的异常都由 `pcall` 捕获。提示从固定字典选择，不显示服务商响应正文、堆栈或配置值；错误报告也只保留白名单计数。`error_displays_ready` 统计已准备的错误显示，`translations_ready` 只统计成功译文；两者都需要回写确认才能说明聊天行已更新。同一消息不会因显示错误而自动再次提交。

## 系统通知门禁

请求前只接收已核验的正文属性、活动事件环指针和聊天事件类型。稳定读取到其他事件类型时，适配器返回 `filtered_event`，状态机不会提交正文，并取消该控件槽已拥有的待处理请求。报告的 `counters.slot_event_filtered` 记录这种槽采样的次数，同一可见事件可能被反复采样，不能将计数当作通知条数。

这条门禁原先已经存在，本次将它与空槽分开报告。没有按“发现”“巢穴”等文字过滤，以免屏蔽玩家正常发言。2026-10-02 用户将游戏语言改为英文后，观察到系统通知没有被翻译且游戏没有崩溃；按用户要求结束通知分类探索，不提供采集探针、不增加猜测的分类规则。这项画面观察不能单独证明模型请求数量，现有 tag 也未被证实专属于玩家。接入依据见 [通知说明](native-chat-research.md#系统通知)。

## 运行边界

启动时核验游戏 DLL 指纹、PE 布局和原生函数签名，通过后才加载网络模块并启用 setter。网络 DLL 从 addon 提取至 `%LOCALAPPDATA%/HD2ChatTranslate/native/<SHA256>.dll`，核验长度、哈希、文件布局并限制依赖搜索到系统目录；线程启动后保留模块至游戏进程结束。

启用后先建立现有消息基线，只处理新消息或变化的正文。每步最多采样四槽、提交一个请求、处理一个响应，共享 16 KiB 读取预算。正文必须是合法 UTF-8、无 NUL 且最多 1023 字节；模型返回的译文最多 16384 字节。加上原文和 10 字节分隔符后，显示文字最多 17417 字节；原始响应协议的上限保持不变。待处理上限 32 条，60 秒过期，网络请求每分钟最多 30 次，并使用有限成功缓存与失败退避。

回写前重新检查根、活动事件、正文指针、唯一正文属性与原文，并核对有界的 UI 历史和行几何，稳定后调用 setter。确认正文属性后才测量行高和重排；未知签名、历史漂移或布局预检失败时不进入回写。属性借用字符串指针，译文缓冲区保留到进程结束；每会话最多 512 个、合计 8 MiB，达到上限保留原文。每个响应最多调用一次 setter。

事件记录没有已证实的唯一 epoch，无法完全排除同槽快速复用且正文再次相同的情况。游戏更新后指纹门禁不通过时停止回写。支持的构建和接入依据见 [接入研究](native-chat-research.md)。

## 停用与卸载

将 `HD2CT_ENABLED` 设为 `0` 后重启游戏可以停用翻译。正常关闭游戏后，在 Arsenal 禁用或移除本模组并重新部署。若其他模组依赖 Shared Loader，卸载本合并包后需保留或恢复它们的独立加载器。插件专用 DLL 缓存可在游戏关闭后删除，环境变量可自行移除。

从源码生成包见 [手动构建指南](build.md)。本机已知崩溃及修复的验收状态见 [修复记录](crash-analysis-2026-10-02.md)。
