# 游戏聊天翻译插件

本页记录带配置窗口的伴随程序版及两种模式共用的聊天回写边界。通过环境变量配置、无需伴随程序的版本见 [独立版说明](chat-standalone.md)。

完整模式已在真实游戏确认：新聊天写入本机文件邮箱，由 Python 伴随程序调用用户配置的大模型，再沿已核验的正文 setter 更新对应的本机聊天行。译文不会发送给其他玩家。

## 配置与运行

运行项目目录的 `pwsh -File run.ps1`，在窗口填写服务商基础地址或完整 Chat Completions 请求地址、模型名称、API Key 和超时。根基础地址与 `/v1` 地址会自动补全，其他自定义路径需要填写完整接口。服务商需要支持 Chat Completions 和 JSON mode。密钥仅在本机使用 Windows DPAPI 保存，不进入游戏 patch。

“测试连接”只发送固定示例，无需勾选“启用翻译服务”，也不会启动聊天处理。测试通过后，勾选启用并点击“开始”；“停止”会停止提交和接收译文。服务状态为运行中且翻译启用时，才会发布游戏端需要的启用心跳。

游戏 addon 在启动时加载，安装或更换 patch 前需要正常退出游戏。2026-10-02 已移除固定显示测试版，部署完整翻译模式至本机独立 patch 21 与 loader patch 22。原 Arsenal patch 0–20 的 21 个主文件摘要逐项核验未变，新增六个文件与来源包和收据均匹配。重复部署与回滚 dry-run 通过。

安装与回滚使用：

```pwsh
pwsh -NoProfile -File tools/deploy_probe.ps1 -Translate -DryRun
pwsh -NoProfile -File tools/deploy_probe.ps1 -Translate
pwsh -NoProfile -File tools/deploy_probe.ps1 -Translate -Rollback
```

保留 `artifacts/HD2ChatTranslate.zip`、loader 来源 ZIP 和 `.local/chat-probe-deployment.json` 至回滚完成；安装脚本拒绝运行中的游戏、不符合指纹的来源和已有槽位覆盖。临时目录内实际安装、幂等部署与实际回滚均已验证。

## 消息与回写边界

启用后先记录当时已有的 64 个控件槽，不发送已有历史；之后只提交新出现或正文变化的条目。中文消息也交模型检测，模型确认中文后严格保留原文，不调用 setter。

游戏每步最多采样四个槽、提交一个请求并处理一个响应，所有对象读取共享 16 KiB 预算。正文必须是有效 UTF-8、无 NUL 且不超过 1023 字节；译文最多 16384 字节。最多保留 32 个待处理请求，60 秒后过期。失败、超时、服务停用或当前消息发生变化时保留原文。

写入前重新读取当前控件和活动事件：要求根、控件槽、唯一正文 key、字符串类型、精确正文指针及原文仍对应，二读稳定后才执行原生 setter。另一个聊天事件推进环 cursor 本身不会令仍然活动的原条目失效。事件环没有已证实的 epoch，当前机制核对的是现存相同正文和属性绑定；它不能证明快速多次复用同一槽后仍是原来的唯一消息。瞬间覆盖、无法读取或复核失败的条目会跳过。

原生属性借用字符串指针，因此译文缓冲区在专用 Lua 全局表中保留到游戏/Lua 进程结束，禁止释放或覆写。每次游戏会话最多保留 512 个缓冲区且总量最多 8 MiB；达到上限保留原文。每个响应最多调用一次 setter，读回未确认也不会再次调用。

## 本机文件协议

邮箱为 `%LOCALAPPDATA%/HD2ChatTranslate/mailbox`：

- `bridge.flag`：至多 64 字节的 `HD2CT1 <GetTickCount64毫秒>\n`，游戏要求心跳年龄不超过三秒；回写前再从磁盘核对。
- `<token>.req`：仅 UTF-8 聊天正文，先写独占临时文件，再无覆盖地原子发布。
- `<token>.res`：`OK\n<显示文字>` 或 `ERR\n<短错误>`，内容只作为文本处理。
- `chat-translate-<session>.json`：固定状态和计数报告，包含待处理数、基线进度、提交、保留原文、失效与回写计数；不含正文、正文散列、token、地址、玩家信息或密钥。

游戏只消费和清理本次会话发布的请求/响应，不删除伴随程序拥有的 `.processing` 文件或其他会话文件。伴随程序使用独占邮箱实例锁、两个网络 worker、每分钟 30 次实际请求与 512 条缓存。停止不能撤回已经发给服务商的网络请求，但停用心跳会阻止游戏回写其结果。

## 兼容性

目前只针对本机已经核验的 Steam build `25480438`、EXE `1.8.46015.0` 与固定 `game.dll` 指纹。游戏更新后门禁不通过时不会调用原生 setter，需要重新定位和核验。Bingus Shared Loader v18 与固定显示试验已在本机工作；资源型 HD2SDK 不提供运行时聊天 API，研究来源和接入证据见 [研究记录](native-chat-research.md)。

## 构建与验收

构建命令为 `python tools/build_chat_probe.py --translate`，输出 `artifacts/HD2ChatTranslate.zip`，仅含 addon 与 manifest，不含伴随程序或用户配置。需要单独运行本项目伴随程序。

- ZIP：34,966 字节，SHA-256 `7533a7889025baa8e5d793de437bc9898b30b1c888c5b5e15a9a8e4b522a613d`。
- addon 主 patch：178,720 字节，SHA-256 `05646782605c5f37ae6fbac32f1dc05cc1e700580a62d58fd8901014b6adcfee`。
- 内嵌 Lua 源码：178,507 字节；完整 LuaJIT 语法编译通过，ZIP CRC 与当前构建输出逐条一致。

`python -m unittest discover -s tests -v` 的 66 项通过，零失败、零跳过，计时 16.767 秒。Python `compileall`、pwsh 解析及 `git diff --check` 通过。新增完整模式回归覆盖 UTF-8、心跳读后时钟、队列与过期、原子邮箱、短读写与文件操作失败、令牌清理所有权、消息漂移、原生 setter spy 与正常读回、缓冲区上限、构建模式及来源保护。离线链路另使用临时目录与真实 CompanionService 线程，由假 Translator 产生译文，Lua core 读到响应后模拟回写一次；未调用真实游戏 setter 或公网。

真实运行先以固定中文试验确认 setter 与字体显示，再用用户配置的完整模型端点核验固定连接示例：HTTP 200、耗时 1.031 秒。连接测试现无需启用翻译，根地址与 `/v1` 地址会自动补全，HTTP 失败显示可信状态码。

随后完整模式在真实游戏运行，用户按流程启用伴随服务并发送英文测试消息，确认原聊天行已变成中文。保存的状态快照记录三条提交、两次原生回写读回确认、一次结果与原文相同而保留；待处理为零，心跳、适配器、响应及回写错误均为零。报告 `artifacts/translate-runtime/confirmed.json` 的 SHA-256 为 `9ab28e4f58f0888abfa1e438755d4429f10e8e9a754c49f0889e99f7b3ef0746`，仅有状态与计数，不保存普通聊天正文或密钥。

至此新游戏聊天 → 本机邮箱 → 用户配置的模型 → 原聊天行替换已完成真实链路验证。该次本机联调不代表所有多人场景、长时间运行或其他游戏版本已验收；现有输入框无法输入中文，真实中文输入仍未测试，中文原文保留由离线模型协议与适配器回归覆盖。
